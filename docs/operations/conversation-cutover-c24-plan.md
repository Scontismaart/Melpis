## PR4 provider and credential plan

- Calendar `src/core/calendar/connection.py:46-59,141-201` serializes refresh across workers using org-scoped advisory lock 604 and GDPR 606; it checks connection epoch and credential version on write. `service.py:107-179` reads availability; `lifecycle.py:65,150,166` performs remote work, verification and local finalization; `repository.py:23-199` fences leases/dispatch/verified/retry. Treat timeouts, remote side effects and uncertain outcomes explicitly; remote Calendar and PostgreSQL cannot share an atomic transaction. Test reconnect, revocation, version/epoch race, duplicate dispatch, stale proof, cancellation during HTTP and reconciliation without real calls.
- Distinct existing external-booking credential race: `src/core/bookings/router.py:122-151,228-229,268-269` sends refresh updates to `src/core/db/repositories/external_booking_repo.py:130-170`, which reads, decrypts, merges then updates the envelope scoped only by organization. Concurrent owner full credential replacement/provider change (`:73-111`) can race and let stale refresh data overwrite newer credentials. `docs/operations/booking-privacy-acl-hardening.md:83-91` explicitly records that credential integrity is not certified; do not conflate this with the Calendar epoch/version fence or reduce impact to availability alone.
- Prepare separate fix proposal with provider identity + version/epoch or equivalent CAS, bounded retry only after revalidation, encryption and secret-safe diagnostics; analyze owner save, refresh, provider switch, deletion, revocation and token rotation. Validate with synthetic credential data, PostgreSQL barriers and competing transactions; prove stale refresh never resurrects old provider credentials. No change to privileges or real provider calls without their own reviewed authorization.
- Define internal-only, optional sync, Google-authoritative and external-provider authority independently, with trusted server-side mapping and UNKNOWN on stale, missing or unreachable evidence. Verify provider idempotency, reconciliation and human handoff; no assumption that a free/busy response locks a remote resource. Gate activation on explicit environment, migration, provider and deployment approvals, successful applicable CI, independent reviews and five-sector evidence.
