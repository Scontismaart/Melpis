# B03 onboarding review — 2026-10-25

## Scope

Review and minimal fixes for the existing seven-step onboarding experience, overview setup checks, and account-and-organization-scoped draft persistence. No backend authorization, tenant resolution, provider connection, OAuth, or account setup flow was added or changed.

## Findings and changes

- The existing onboarding pane had no canonical dashboard route or initializer path. The route now opens the existing seven steps directly and the overview checklist links to it.
- Drafts now use a per-account and per-organization storage key. Organization-only and unscoped legacy drafts are ignored because they have no reliable account provenance. Logout or organization changes clear prior in-memory form state; saved drafts remain isolated. Async onboarding responses check the active user/organization and in-memory session epoch before updating the UI, including logout followed by login to the same account.
- Overview setup checks previously treated request failures as completed setup. Failed requests, invalid JSON, or invalid response shapes now produce an unavailable state with retry; they cannot set WhatsApp, documents, or opening hours to ready.
- Existing wizard strings are connected to the repository i18n mechanism in Italian, English, French, German, and Spanish. All five `dashboard.json` files are synchronized across `locales/`, `web/locales/`, and `web/landing/locales/`; each language's three copies have identical SHA-256 hashes. WhatsApp is described as not verified or connected by this guide; Google Calendar remains an optional settings concern.

## Security and product boundaries reviewed

- Backend organization scoping and role checks remain authoritative and unchanged. This change adds no client flag that grants access, no endpoint, and no role behavior.
- The existing upload and preview endpoints remain in use. No provider was called and no real account was linked.
- A successful document upload marks the wizard checkbox only when its response includes a positive integer indexed count and nonempty document ID and name. A forbidden profile response is shown as an error and does not fall through to local draft recovery.
- Trial RAG availability is not changed; existing plan enforcement remains server-side. The wizard does not introduce a client-side plan bypass.
- Existing responsive layout rules were retained; no layout redesign or CSS changes were needed.
- The existing test step remains an existing UI action. The wizard copy now clarifies that it does not verify a live WhatsApp connection.
